Browser verification on 3 October 2026

Method
The real Go fixtures run through cmd/terma-browser and xterm.js in the Codex in-app browser. The browser viewport is its default 1280 by 720. Comparison sessions use fixed terminal dimensions of 100 columns by 30 rows. Each fixture is identical between the baseline and final implementation. Browser launch tokens are intentionally omitted.

Unicode autocomplete
First reproduced with the joined emoji suggestion. Enter produced cursor 3 in a one-grapheme buffer. Typing ! exited with a slice-bounds panic. The fixed code accepted the emoji at cursor 1 and allowed the next keystroke.
The browser terminal rendered joined-emoji widths inconsistently during incremental output. To make screenshots legible, the final screenshot fixture uses e followed by a combining accent and formats status text with ASCII escapes. The same baseline failure occurred at cursor 2 in a one-grapheme buffer. Typing ! crashed. The final app accepted the suggestion at cursor 1, then displayed é! at cursor 2 and remained connected.

Visibility
Baseline displayed neither the visible panel nor its reserved space. Pressing v changed visible status without recovering the panel or layout.
Final displayed the panel and Count click button. A mouse click incremented the counter from 0 to 1. Pressing v hid the panel without moving the footer. Clicking the old button position and pressing Enter left the counter at 1. Showing the panel again restored keyboard activation. Regression tests also verify focus and hit-target exclusion, floats, layout growth, and incremental/full-render parity.
