The experiment

  • Baseline: remote main at ad4bdcb, with the same benchmark harness copied into a pristine source checkout.
  • Apple M4 Pro, macOS arm64, Go 1.25.5, GOMAXPROCS=14. Both test binaries were compiled before timing.
  • Baseline and after suites alternated across five samples, one process at a time, with -benchtime=200ms and allocation reporting. Charts show medians.
  • Renderer scenarios use an in-memory terminal at 120 × 40 cells. Fixture setup and initial rendering are excluded from the timed loop.

What the numbers do not say

  • No terminal I/O, app event loop, frame throttling, or network latency is included. This is not an FPS claim.
  • Repeated samples capture local variation; they are not cross-machine confidence intervals. This run is a reference, not a portable threshold.
  • Selector snapshot allocation counts fall sharply, while allocated bytes can rise slightly because of Go allocator size classes.
  • Visible behavior was checked through real demos in terma-browser, alongside tests and existing snapshots.

Performance improved.
The behavior was checked.

42 existing text snapshots stayed unchanged. Full tests and the race detector passed. Rich-text output matched the previous implementation across 2,000 seeded differential cases, and 65,158 fuzz cases passed.

One edge case also became safe to render: a CJK character in a one-cell hard-wrap width timed out after 500 ms on the baseline; the fixed layout and painting paths complete. That is a correctness result, separate from the timing charts.

What we exercised in the browser
  • Final gallery check (ad4bdcb): list cursor movement, range selection, appending ten rows, mouse selection, and tree lazy loading, navigation, and collapse at the default viewport. Full tests and the race detector were rerun after the final upstream refresh.
  • Earlier focused checks: the following demos exercised the same performance fixes before that upstream refresh.
  • Todo app: text entry, cursor movement, task completion, and a dialog at the default viewport and fixed 100 × 30 terminal dimensions.
  • Markup demo: theme repainting and mouse scrolling at 100 × 30 cells.
  • Directory tree: mouse selection, nested expansion, collapse, navigation past hidden descendants, multi-selection, filtering to a descendant, and clearing the filter. Inspected screenshots and accessible terminal text at the default 1280 × 720 browser viewport.
Reproduce the measurements
go test . -run '^$' \
  -bench 'Benchmark(TextPerf|RetainedNestedLayout|RetainedPartialDamage|SignalSelectorFanout|TreeFlattenVisible|ReactivityLeaf|ReactivityTextSize|ReactivityListCursor)' \
  -benchmem -benchtime=200ms -count=5

go test ./layout -run '^$' -bench '^BenchmarkTextPerf' \
  -benchmem -benchtime=200ms -count=5

go test ./...
go test -race ./...

Use the same Go version and machine settings for both revisions. Copy the benchmark-only harness to the baseline checkout; new regression tests describe the fixed behavior and may intentionally fail on the baseline. Run one benchmark process at a time.
